# 쿠라맛챠 노래책 — 검색 UI 구현기획서

## 0. 목적

이 문서는 쿠라맛챠 노래책 검색 엔진을 Google Sheets 안에서 사용자 친화적인 검색 UI로 만드는 구현 계획서다.

목표는 Streamlit이나 별도 웹앱이 아니라, 현재 Google Sheets 구조를 유지하면서 **공식 노래 검색 페이지처럼 보이는 v1.0 MVP**를 만드는 것이다.

---

## 1. 현재 판단

### 1.1 Streamlit은 당장 보류

Streamlit은 검색 UI, 카드, 버튼, 모바일 대응을 깔끔하게 구현할 수 있다.
하지만 다음 문제가 있다.

| 문제 | 설명 |
|---|---|
| 운영 부담 | 방송 하나를 위해 앱 구동/배포/유지 필요 |
| 데이터 연동 | Google Sheets 또는 CSV와 동기화 필요 |
| 장기 관리 | 사용자가 늘기 전에는 과투자 |
| 링크 안정성 | 시트 링크보다 관리 포인트가 늘어남 |

따라서 현재 단계에서는 Google Sheets MVP가 맞다.

### 1.2 Google Sheets로 구현 가능한 목표

이미지 mockup처럼 완전한 웹앱은 어렵다.
하지만 다음은 가능하다.

| 목표 | 구현 가능성 | 방식 |
|---|---:|---|
| 큰 검색창 | 가능 | 병합 셀 + 입력칸 |
| 드롭다운 필터 | 가능 | TAXONOMY 기반 데이터 확인 |
| 카드형 결과 | 가능 | 미리 서식 잡은 카드 슬롯 + helper 참조 |
| 링크 버튼 느낌 | 가능 | `HYPERLINK(url, "▶ 영상")` |
| 랜덤 추천 | 가능 | 수식형 RAND/SORT 또는 Apps Script later |
| PC/모바일 분리 | 가능 | 별도 시트 |
| 웹앱식 그림자 | 어려움 | 테두리/배경색으로 대체 |
| 반응형 UI | 불가 | PC/모바일 시트 분리 |

## 2. 최종 목표 구조

v1.0에서 목표하는 구조는 다음이다.

```text
쿠라s 노래책~!        원본 DB
        ↓
검색_ENGINE          기존 작동 검색엔진 보존
        ↓
QUERY_BUILDER        QUERY 조건 조각 생성
        ↓
CARD_HELPER          검색 결과를 카드 표시용으로 재조합
        ↓
검색_UI_PC           데스크탑용 사용자 화면
검색_UI_MOBILE       모바일용 사용자 화면
```

## 3. 시트별 역할

| 시트명 | 공개 | 역할 |
|---|---|---|
| `메인!` | 공개 | 사용 안내, PC/모바일 링크, 버전 정보 |
| `검색_UI_PC` | 공개 | 데스크탑용 카드형 검색 화면 |
| `검색_UI_MOBILE` | 공개 | 모바일 세로형 검색 화면 |
| `검색_ENGINE` | 숨김 | 현재 `검색창` 기능을 보존한 검색 결과 엔진 |
| `QUERY_BUILDER` | 숨김 | 검색 조건 조각 생성 |
| `CARD_HELPER` | 숨김 | 검색 결과를 UI 카드용으로 변환 |
| `TAXONOMY` | 숨김/보호 | 드롭다운 선택지 관리 |
| `쿠라s 노래책~!` | 보호 | DB_RAW |
| `BACKUP_ENGINE` | 숨김 | 작동본 백업 |

목표:

### PC UI 추천 배치

| 범위 | 내용 |
|---|---|
| B1:J1 | 타이틀: `🍵 쿠라맛챠 노래책` |
| B2:J2 | 설명: `제목, 가수, OST, 틱톡, 요네즈처럼 검색해보세요` |

| K3:N8 | 랜덤 추천 박스 |

| K10:N18 | 사용 예시/도움말 |

### PC 카드형 결과

기존 9개 결과 컬럼을 그대로 노출하지 않고, 5개 의미 컬럼으로 재조합한다.

| 카드 컬럼 | 표시 내용 |
|---|---|
| 곡 | 제목 + 번역명 |
| 가수/언어 | 가수 + 한국명 + 언어 |
| 장르/주제 | 장르 + 상황/대상/감정 |
| 출처 | 비고 |
| 링크 | `▶ 영상` |

예시:

```text
곡: なんでもないや
    아무것도 아니야

가수/언어: RADWIMPS
           래드윔프스 · 일본어

장르/주제: 발라드 / 팝
           사랑 / 재회 / 그리움

출처: 애니 영화 OST 너의 이름은
링크: ▶ 영상
```

## v1.1 — 모바일 세로 UI

목표:

> 모바일 세로 화면에서 좌우 스크롤 없이 곡을 찾을 수 있게 한다.

### 모바일 원칙

| 원칙 | 설명 |
|---|---|
| 가로폭 최소화 | A:D 또는 A:E 안에 주요 UI 종료 |
| 한 곡 = 한 카드 | 세로 스크롤 중심 |
| 필터 축소 | 기본 필터는 3~4개만 |
| 고급 필터 숨김 | 아래쪽 또는 별도 영역 |
| 링크는 큰 셀 | 터치하기 쉽게 |

### 모바일 추천 배치

| 범위 | 내용 |
|---|---|
| A1:D1 | `🍵 쿠라맛챠 노래책` |
| A3:D3 | 자유검색 입력 |
| A5:D5 | 기본 필터: 언어/장르/분위기/출처 |
| A7:D9 | `🎲 지금 부를 곡 추천` |
| A11:D40 | 결과 카드 8개 |

### 모바일 카드 구조

모바일은 한 카드가 여러 줄로 표시된다.

```text
なんでもないや
아무것도 아니야
RADWIMPS · 일본어
발라드 / 팝
사랑 / 재회 / 그리움
애니 영화 OST 너의 이름은
```

링크는 같은 카드 안에 일부 텍스트만 하이퍼링크 처리하기 어렵다.
따라서 모바일은 다음 둘 중 하나로 구현한다.

| 방식 | 설명 | 추천 |
|---|---|---|
| 한 셀 카드 + 별도 링크 셀 | 카드 텍스트와 `▶ 영상`을 분리 | 추천 |
| 카드 내 URL 포함 | 보기 지저분함 | 비추 |

## v1.3 — 가사_INDEX 초기 구현

사용자는 가사 기능을 사용성의 중요한 준비단계로 본다.
전체 가사를 직접 저장하지 않고, 가사/발음/해석 링크 허브를 빠르게 만든다.

### 가사_INDEX 컬럼 초안

| 컬럼 | 설명 |
|---|---|
| song_id | DB와 연결 |
| 제목 | 곡명 |
| 가사링크 | 원문 가사 |
| 발음링크 | 한글 발음/독음 |
| 해석링크 | 한국어 해석 |
| 노래방/MR | MR 또는 노래방 영상 |
| 발음주의 | 방송용 발음 메모 |
| 시작가사 | 곡 찾기용 첫 소절 |
| 주의사항 | 저작권/방송 주의/난이도 |
| 상태 | 완료/검수필요/링크필요 |

### 원칙

- 전체 가사를 시트에 직접 저장하지 않는다.
- 외국어 곡은 원문+발음+의미가 같이 있는 자료를 우선 찾는다.
- 링크 허브부터 만든다.

## 5. CARD_HELPER 설계

### 5.1 PC 카드 helper

검색_ENGINE 결과가 `B5:J`에 있다고 가정한다.

`CARD_HELPER`에서 다음 컬럼을 만든다.

| 열 | 내용 |
|---|---|
| A | 곡 정보 |
| B | 가수/언어 |
| C | 장르/주제 |
| D | 비고 |
| E | 링크 |

### 5.2 PC helper 수식 예시

곡 정보:

```gs
=IF(
  검색_ENGINE!B5="",
  "",
  TEXTJOIN(CHAR(10), TRUE, 검색_ENGINE!B5, 검색_ENGINE!C5)
)
```

가수/언어:

```gs
=IF(
  검색_ENGINE!B5="",
  "",
  TEXTJOIN(CHAR(10), TRUE, 검색_ENGINE!D5, 검색_ENGINE!E5 & " · " & 검색_ENGINE!F5)
)
```

장르/주제:

```gs
=IF(
  검색_ENGINE!B5="",
  "",
  TEXTJOIN(CHAR(10), TRUE, 검색_ENGINE!G5, 검색_ENGINE!H5)
)
```

비고:

```gs
=IF(검색_ENGINE!B5="", "", 검색_ENGINE!I5)
```

링크:

```gs
=IF(
  검색_ENGINE!J5="",
  "",
  HYPERLINK(검색_ENGINE!J5, "▶ 영상")
)
```

주의:

- 현재 링크 값이 URL이 아니라 YouTube 제목/검색 텍스트인 행도 있다.
- URL이 아닌 텍스트에 `HYPERLINK`를 쓰면 깨질 수 있다.
- 링크URL 정규화가 필요하다.

## 8. 즉시 실행 순서

### Phase 1 — 보존

1. 현재 파일 백업
2. `검색창` 복제 → `검색_ENGINE`
3. `QUERY_BUILDER` 숨김 처리
4. `TAXONOMY` 숨김 또는 보호

### Phase 2 — PC UI 초안

1. `검색_UI_PC_TABLECARD` 생성
2. 제목/검색창/필터 배치
3. 검색 입력값을 `검색_ENGINE` 또는 `QUERY_BUILDER`로 연결
4. `CARD_HELPER` 생성
5. 상위 10개 카드 슬롯 표시
6. 랜덤 박스 추가

### Phase 3 — 모바일 초안

1. `검색_UI_MOBILE_CARD` 생성
2. A:D 범위 안에 세로 UI 구성
3. 기본 필터만 노출
4. 1열 카드 8개 표시
5. 모바일 확대율 테스트

### Phase 4 — 가사_INDEX

1. 가사_INDEX 시트 생성
2. song_id/제목/가사링크/발음링크/해석링크 구조 만들기
3. 우선 자주 부를 곡 5~10개만 입력
