# 쿠라's 노래책 — PROJECT_STATE_v1_0_WEB

## 0. 문서 목적

이 문서는 쿠라's 노래책 GitHub Pages Web v1.0 Beta의 현재 실제 구현 상태를 기록한다.

이 문서는 Google Sheets MVP 문서가 아니다.  
이 문서는 앞으로 Codex, GPT, 운영자가 현재 상태를 혼동하지 않도록 하는 최신 상태 보고서다.

---

## 1. 현재 프로젝트 정의

쿠라's 노래책은 스트리머 “쿠라맛챠” 방송용 팬메이드 노래 검색 사이트다.

핵심 목적:

> 스트리머와 시청자가 방송 중 곡을 빠르게 찾고, 영상/가사 링크로 이동하며, 랜덤 추천이나 필터를 통해 곡을 고를 수 있게 하는 노래 검색 페이지.

현재 v1.0은 GitHub Pages 기반 정적 웹사이트로 공개되었다.

---

## 2. 현재 기술 구조

```text
GitHub Pages
Plain HTML/CSS/JavaScript
data/songs.json
YouTube thumbnail links
No backend
No login
No user submission storage
```

현재 주요 파일:

```text
index.html          # 메인 포털
search.html         # 검색 결과 페이지
src/portal.js       # 포털 검색/이동 로직
src/app.js          # 검색/필터/정렬/랜덤/카드 렌더링
src/style.css       # 공통 스타일
data/songs.json     # 공식 웹 DB
assets/             # hero/background/visual assets
docs/               # 문서
```

---

## 3. 현재 페이지 역할

### 3.1 `index.html`

메인 포털 페이지.

역할:

- 첫 진입점
- 큰 검색창
- 빠른 검색 예시
- 전체 곡 보기
- 랜덤 추천 / 검색 도움말 안내
- 말차, 아이보리, 핑크 해파리, 벚꽃 감성의 브랜딩

### 3.2 `search.html`

실제 검색 결과 페이지.

역할:

- 검색어 기반 곡 검색
- 필터
- 정렬
- Pick 먼저 보기
- 랜덤 추천
- 영상 썸네일 링크
- 가사 링크
- 부른 횟수 표시
- PC 중심 실사용 검색 UI

---

## 4. 현재 DB 기준

현재 공식 웹 DB는 다음 파일이다.

```text
data/songs.json
```

Google Sheets / xlsx는 더 이상 일반 운영의 source of truth가 아니다.  
단, legacy import, 백업, 과거 구조 확인용으로 유지할 수 있다.

---

## 5. 현재 구현 완료 기능

### 검색

- 자유검색
- 공백 기준 단어 분리
- 단어 간 AND
- 필드 간 OR
- 한국어/일본어/영어 일부 대응
- `tags`를 통한 alias 보강 가능

### 필터

현재 공개 필터:

- 언어
- 장르
- 분위기
- Pick 먼저

필터 옵션은 `data/songs.json`에 실제 존재하는 값 기반으로 생성한다.

### 정렬

- 기본순
- 제목순
- 가수순
- 부른 횟수순

### 랜덤 추천

- 전체 곡 랜덤
- 현재 결과 랜덤
- 랜덤 카드 표시
- 썸네일 표시
- 가사 링크 표시

### 결과 카드

- 썸네일
- 제목
- 번역명
- 가수 / 한국명 / 언어
- songIntro
- 장르/출처 메타
- 핵심 칩
- 가사 버튼
- 부른 횟수
- Pick 표시

### 영상/가사

- 영상은 썸네일 클릭으로 새 탭 열기
- 가사 링크는 별도 버튼
- YouTube embed modal은 v1.0에서 제외

## 6. 현재 디자인 상태

디자인 방향:

- 말차
- 아이보리
- 연핑크
- 핑크 해파리
- 벚꽃
- 일본 개인 팬사이트
- 애니 굿즈샵 / 카드 컬렉션 감성
- 귀엽지만 유아틱하지 않음
- 검색 페이지로서 실용성 우선

현재 반응:

- 핑크 해파리 방향은 긍정적 반응을 얻음.
- 파란 해파리가 아니라 핑크 해파리인 점이 캐릭터/취향 이해로 받아들여짐.

## 9. 현재 운영 원칙

1. `data/songs.json`을 공식 웹 DB로 본다.
2. Google Sheets 문서는 legacy/reference로 유지한다.
3. 곡 추가는 GPT 조사 결과를 JSON 포맷으로 받은 뒤 검증한다.
4. 불확실한 곡 정보는 추정하지 않고 빈 값 또는 TODO로 남긴다.
5. 방송 주인의 공간을 존중하고, 과도한 홍보/요청 기능은 천천히 도입한다.
6. 사용자 피드백은 초기에는 게시물 댓글 중심으로 받는다.
7. 공식 요청/제보 폼은 v1.1 이후 검토한다.
